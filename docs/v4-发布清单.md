# EasySSH v4 发布清单（release checklist）

> v4 的发布不走 3.x 的 `easyssh-site/tools/release.sh`（那是 Electron 构建流），而是下列手工步骤。
> 2026-11-02 v4.3.0 首次按此清单完整执行并验证。

## 1. 构建（easyssh4 仓库）
```bash
bash scripts/build-v4-setup.sh     # MSVC 交叉构建 + NSIS 单文件引导器
# 产物: dist/EasySSH-<ver>.exe (引导器) + target/x86_64-pc-windows-msvc/release/easyssh.exe (裸 exe)
```
注意：发布口径是 **MSVC**（AV 误报率低），不要用 build-v4.sh 的 mingw 产物。

## 2. 官网产物落位（EasySSH 仓库）
- `EasySSH/release/EasySSH-<ver>.exe` ← 引导器
- `EasySSH/dist/EasySSH-<ver>-update.exe` ← 裸 exe（升级载荷）
- `EasySSH/dist/EasySSH-<ver>-portable.exe` ← 裸 exe
- `EasySSH/dist/EasySSH-<ver>-win32-x64-portable.zip` ← zip(EasySSH.exe)

## 3. 发布说明（权威源）
- `EasySSH/README.md`「版本更新历史记录」新增 `### v<ver> (日期)` 小节 —— 官网 changelog/升级 notes 全部由此生成，**必须先改**

## 4. 官网功能总览页
- 梳理本版新增/变更功能，更新 `easyssh-site/site/features.html` 对应分区功能卡
  （分区：连接与会话 / 终端体验 / 文件传输 / 网络与转发 / 密钥与安全 / 升级与维护）
- 功能卡带版本号标注（如 "（v4.3.0）"），release.sh [3.5/5] 步骤会强制校验
- 如改了 site.js / css，同步更新各页面引用的 `?v=` 缓存版本号

## 5. 官网同步 + 校验
```bash
cd /opt/dsh/workspace/easyssh-site
node tools/sync.js                 # 生成 site-data.json / downloads 拷贝 / .enc 加密包 / api
node tools/update-selftest.js      # 加密协议自测
bash tools/healthcheck.sh          # 站点自检
# features.html 校验已内置在 release.sh [3.5/5]；v4 手工发布时同样要确认
grep -q "<ver>" site/features.html || echo "!! 记得更新功能总览页"
```
说明：`/api/update/check` 是动态服务（读 site-data.json 实时封包），旧版 webroot 中静态
`api/update/check` 文件已不再是生效数据源；downloads/ 与 data/ 为 dsh 可写，页面文件由
root 侧定时任务（约 5 分钟）从 site/ 自动同步部署。

## 6. 验证（上线后必做）
- `curl -s https://easyssh.cn/data/site-data.json | jq .latestVersion` → 新版本
- 拉线上 `.enc` 用 `tools/update-crypto.js decryptFile` 解密，比对明文 SHA-256 与清单一致（端到端）
- `curl https://easyssh.cn/features.html` 确认功能页已含新版本标注
- GitHub Release 创建（tag v<ver>，附引导器 exe + portable zip）；EasySSH 仓库推 origin；
  Gitee 凭据本机不存在，需用 Gitee 私人令牌单独推送

## 7. easyssh4 源码仓库
- 提交全部改动、打 tag v<ver>、推送 origin v4-dev --tags（历史较大，推送耐心等待）
