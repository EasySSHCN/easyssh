# EasySSH v4 升级设计方案

> 基于 v4 现状（Tauri 2 + russh 0.45 + tokio，easyssh-core 加密/配置层，单文件 renderer.js UI）制定。
> 目标：功能更强、更快、更安全、更抗故障，同时保持 3.x 配置兼容与 <20MB 包体优势。

---

## 0. 现状盘点（方案依据）

| 维度 | 现状 | 主要短板 |
|---|---|---|
| 架构 | Tauri 2 + russh 0.45，`SessionMap = HashMap<u64, SessionHandle>` | russh 0.45 已落后多个版本；会话无状态机、无自动重连策略层 |
| 加密 | AES-256-GCM，PBKDF2-SHA256 100k 迭代，`enc:v1`/`wrap:v1` | 迭代次数偏低；不接入 OS 级凭据保护；无算法策略管控 |
| 主机密钥 | 指纹 TOFU 弹窗（信任/拒绝/替换） | 无 known_hosts 严格校验、无密钥轮换检测、无算法降级告警 |
| 配置 | exe 同目录 config.json / config.key(.enc/.bak)，SECRET_FIELDS 仅 password/passphrase | 写入非原子化程度待确认；无 schema 版本迁移；秘密字段覆盖不全 |
| UI | 单文件 renderer.js ~1900 行 + tauri-bridge.js | 无构建管线、无模块化、渲染性能依赖默认 xterm 配置 |
| 发布 | NSIS + 自更新（ureq） | 更新包签名校验需确认/强化 |
| Release | opt-level="z"、panic=abort | 极致压体积牺牲热路径性能；panic 即退出无恢复 |

## 1. 功能需求扩展与强化

### 1.1 终端能力
- **自动重连 + 会话恢复**：断线后指数退避重连（1s→2s→4s…上限 60s），网络闪断无感恢复；配合 `tmux/screen` 集成提示（检测到 TMUX 环境时一键 attach）。
- **会话录制与回放**：asciinema cast 格式录制终端输出，支持回放与导出（审计/教学场景）。
- **trzsz / Zmodem（rz/sz）**：终端内直接拖拽传文件，走已有 xfer 通道。
- **宏与代码片段库**：常用命令快捷发送，支持变量占位与多行脚本，按会话/全局两级管理。
- **分屏与广播**：一个标签页内水平/垂直分屏；向多个选中会话同时输入（运维批量场景）。
- **Sync input（同步输入）** 与 **只读锁定**（防止误操作生产机）。

### 1.2 连接与跳转
- **跳板机链（Jump Chain）**：支持多级 ProxyJump，UI 可视化编辑链路（`A → B → C`），复用已有 pf 模块的转发基础设施。
- **ProxyCommand / SOCKS5 / HTTP 代理**前置。
- **Agent 转发（agent forwarding）** 与 **SSH Agent（Pageant/OpenSSH agent）对接**，减少私钥常驻。
- **连接分组/标签/搜索**：会话树形分组、按主机/标签/最近使用检索；文件夹级批量连接。
- **known_hosts 管理界面**：查看、删除、批量信任记录，显示各主机算法与指纹。

### 1.3 SFTP 强化
- **双面板文件管理器**：本地↔远程拖拽、多选、断点续传（续传 offset 记录）、校验（sha256 抽检）。
- **传输队列与限速**：并发数可配（默认 4）、全局/单任务限速、失败自动重试 N 次。
- **远程编辑**：下载→调用系统编辑器→保存自动回传（带 mtime 冲突检测）。
- **路径收藏/历史**、大目录虚拟滚动列表。

### 1.4 其他
- **命令面板（Ctrl+Shift+P）**：统一入口执行任意动作（连接/主题/设置/片段）。
- **SSH Config（~/.ssh/config）导入**：自动转换已有配置。
- **主题市场/自定义主题**、字体设置面板（当前硬编码项外置）。
- **便携模式与安装模式并存**（保留 3.x exe 同目录布局，新增 `%APPDATA%` 模式可选）。

## 2. 执行效率提升

### 2.1 后端（Rust 侧）
- **russh 升级 0.45 → 0.5x**：新版在 channel window 管理、keepalive、算法协商上有明显改进；升级是后续多数功能（agent 转发、ProxyJump）的地基。
- **会话状态机重构**：`SessionMap` 从裸 HashMap 改为带状态（Connecting/Connected/Reconnecting/Closed）的会话管理器，事件通过统一的 `SessionEvent` bus 推给前端，替代目前零散的 invoke/emit。
- **SFTP 管道化**：读/写请求流水线（pipeline depth 8–16）+ 并发分块，大文件吞吐预计提升 3–5 倍；配合 `russh-sftp` 的 window size 调大。
- **输出背压**：终端输出经有界 channel（如 1MB 环形缓冲）批量合帧推送（16ms 合帧窗口），避免高频输出（如 `cat` 大文件）打爆 IPC。
- **tokio 运行时隔离**：SSH IO 与磁盘 IO（配置/SFTP 落盘）分 task 优先级，避免大传输阻塞终端帧。

### 2.2 前端（UI 侧）
- **引入 Vite 构建管线**：renderer.js 拆分为 modules（tabs/term/sftp/settings/…），tree-shake + 压缩；保留零框架或仅引入轻量（如 preact）按需决定。
- **xterm 渲染优化**：启用 WebGL renderer（`@xterm/addon-webgl`），scrollback 上限可配（默认 5000 行），关闭不必要的 ligature/宽字符处理。
- **查找/搜索**：改用 `@xterm/addon-search` 原生高亮，替代手写 findInText。
- **启动速度**：懒加载 SFTP/设置面板模块；首帧只初始化终端与连接列表。

## 3. 安全加强

### 3.1 凭据保护
- **PBKDF2 100k → Argon2id**（`argon2` crate，内存 64MB/迭代 3），主密码派生抗 GPU 暴力破解；提供 `wrap:v2` 前缀并保留 v1 解密兼容 + 首次解锁后自动迁移。
- **OS 级密钥保管集成**：优先用 Windows DPAPI / macOS Keychain / Linux libsecret 保护 config.key（`keyring` crate），主密码可选"免输入、仅本机解密"模式；两套模式互为回退。
- **秘密字段扩面**：SECRET_FIELDS 从 `[password, passphrase]` 扩展到 include 私钥文件内容（若选择存库）、自定义宏中的敏感变量、代理凭据。

### 3.2 传输与算法策略
- **算法白名单策略**：禁用 ssh-rsa(SHA-1)、CBC 模式、diffie-hellman-group1/sha1 类 KEX；提供"兼容模式"开关供老旧设备，UI 明确风险提示。
- **known_hosts 严格模式**：默认按 OpenSSH known_hosts 语义校验；主机密钥变更（rotation）单独告警级别；支持 @cert-authority。
- **首次连接指纹确认**保留 TOFU，但补充：显示完整公钥、算法、可复制指纹，且记录"首次信任时间/来源"。

### 3.3 应用层
- **更新签名校验**：自更新包强制 ed25519/minisign 签名验证（含 SHA-256 摘要双校验），验签失败拒绝安装并回滚；发布流水线私钥与 CI 分离。
- **Tauri CSP 收紧**：`csp` 配置默认 `default-src 'self'`，禁 inline script（Vite 构建后可控）；`tauri-bridge` 白名单化 invoke 命令。
- **剪贴板与日志脱敏**：反馈/日志上传前二次脱敏（host、IP、用户名、路径模式过滤）；崩溃报告默认关闭自动上传。
- **会话锁定**：全局快捷键锁定 UI（复用主密码），闲置 N 分钟自动锁定可配。
- **窗口标题注入防护**：终端标题仅展示转义文本，防止 OSC 序列伪造（如伪装 sudo 提示）。

## 4. 冗余与可靠性加强

### 4.1 数据冗余
- **配置写入原子化**：`config.json.tmp → fsync → rename` 三步写，杜绝半写损坏；保留滚动备份 `config.json.bak.{1..5}`（按修改时间轮转）。
- **config.key 三副本**：`.enc` 主文件 + `.bak` + OS keyring（如启用），任一损坏可恢复；解锁时校验 DEK 可解密抽样字段，失败立即走恢复链。
- **schema 版本迁移**：config.json 增加 `"schemaVersion"`，启动时按序执行迁移函数（v4 沿用 3.x 布局已验证，后续升级有据可依）。

### 4.2 进程级冗余
- **panic 策略调整**：当前 `panic = "abort"` 使任何 Rust panic 直接闪退；改为 release 保留 unwind（体积换稳定，预计 +1~2MB），并在 main 外层捕获 panic 记录到本地崩溃日志。
- **连接看门狗**：keepalive（server-alive-interval 15s，3 次失败判定断线）+ 后台检测半开连接（TCP zero-window/静默），主动触发重连状态机。
- **传输断点续传与校验**：SFTP 任务落盘 `.easyssh-transfer.json` 状态文件，应用崩溃后重启可续传；完成后抽样 sha256 校验。
- **更新失败回滚**：安装新版本前保留上一版可执行文件副本，启动自检失败自动回滚并提示。

### 4.3 观测性
- **结构化日志**：统一 `tracing` + 滚动文件（按天、按大小），级别 UI 可调；连接/SFTP/更新三大链路有可追踪事件 ID。
- **自检命令**：设置页"诊断"按钮一键导出脱敏诊断包（配置结构、日志、算法协商记录），支撑用户支持流程（配合现有 feedback 模块）。

## 5. 性能加强

| 项 | 措施 | 预期收益 |
|---|---|---|
| 包体 vs 速度 | release 拆 profile：`opt-level=3` 用于 ssh/sftp 热路径（可用 `[profile.release.package]` 按包覆盖），全局保持 `z`；`panic` 改 unwind | 吞吐↑，包体预计 20→22MB 内可控 |
| 终端渲染 | WebGL renderer + 合帧推送 + scrollback 环形缓冲 | 高频输出掉帧显著减少，内存占用降 30%+ |
| SFTP 吞吐 | pipeline + 并发分块 + 调大 window/packet size | 大文件传输 3–5× |
| 启动时间 | 懒加载 + 延迟初始化 updater/feedback | 冷启动 <500ms（WebView2 除外） |
| 内存 | 会话关闭即 Drop 句柄、term dispose；长会话 scrollback 上限+压缩 | 多标签（20+）稳定运行 |
| IPC | 事件合帧、二进制（base64→直接 Vec<u8> 通道）传输 | 输出延迟与 CPU 双降 |

性能验收基线：`cat 100MB 文件`不掉帧、SFTP 千兆内网 ≥300MB/s（视磁盘）、20 标签常驻内存 <600MB、冷启动 <1s。

## 6. 落地路线图（建议 4 个里程碑）

**M1 — 地基（~2 周）**
russh 升级、会话状态机 + 自动重连、配置原子写/备份/schemaVersion、panic 调整、tracing 日志。

**M2 — 安全（~2 周）**
Argon2id（wrap:v2 + 兼容迁移）、OS keyring、算法策略白名单、known_hosts 严格模式、更新签名校验、CSP 收紧。

**M3 — 效率与功能（~3 周）**
Vite 模块化 + WebGL 渲染 + 合帧、SFTP 管道化与断点续传、跳板链、trzsz、片段库、命令面板。

**M4 — 体验补全（~2 周）**
双面板 SFTP、分屏/广播、会话录制、ssh config 导入、诊断包、发布流水线（签名 + CI + 自动更新灰度）。

每个里程碑保持 zip ≤20MB 红线复核与 3.x 配置兼容回归测试（现有 config.json/config.key 直接可用）。

## 7. 风险与决策点（需要你拍板）

1. **russh 0.45 → 0.5x**：API 变动不小，但拖得越久迁移成本越高 —— 建议 M1 立即做。
2. **panic=abort → unwind**：+1~2MB 体积换稳定性，是否接受？
3. **OS keyring 与便携模式冲突**：便携模式（U 盘场景）无法用 DPAPI，需保持纯主密码模式为兜底。
4. **UI 是否引入轻量框架**：现阶段建议 Vite + 原生模块化即可，双面板 SFTP 复杂后再评估 preact。
5. **自动更新灰度**：是否需要分渠道（stable/beta）发布，影响 updater 设计。
