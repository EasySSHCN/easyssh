# EasySSH 需求变更记录池

> 维护规则：任何需求变更先在此登记（含编号、日期、内容、影响面、实施版本），再改代码。
> 编号规则：F-R<序号>-<流水>；状态：待评审 / 已实现 / 已开发未发布（代码已合入、随下次满足发布条件的新版本一并发布） / 暂缓 / 已关闭。
>
> **机器池登记流程（强制）**：本文档是人读的需求池；`reqpool\requirements-pool.json` 是发布巡检唯一权威数据源。
> 凡需参与「状态=记录 ≥3 条触发发布周期」计数的条目（含"已开发未发布"补录），必须走脚本流程登记，禁止手工/内联命令直接改 JSON：
> 1. 条目 JSON 写到 `reqpool\pending-items\R-<yyyymmdd>-<流水>.json`（字段：id/type/title/source/sourceRef/detail/createdAt/statusHistory/status；detail 中注明【开发状态】与【剩余工作】）；
> 2. 执行 `powershell -ExecutionPolicy Bypass -File scripts\pool-add.ps1 -ItemFile <该文件>`——脚本校验必填字段、id 唯一与格式、status 口径（记录/待开发）、记录状态禁止携带 releaseVersion、statusHistory 留痕一致，写后读回复核并留日志；
> 3. 校验不过 = 条目不入池（脏数据不进触发计数）。
> "已开发未发布"条目的 detail 必须写明"发布时无需再改代码，直接走 版本号+README+构建+push"，发布会话读到即跳过重复开发。
