## 1. 产品定位与愿景

### 1.1 一句话定位

> **EasySSH v5.0：面向中文运维场景的轻量级、绿色便携、安全可信的 SSH/SFTP 工作台——10MB 级体积、秒级启动、v4 配置零迁移成本。**

### 1.2 产品愿景

EasySSH 始终坚持三条产品底线，v5.0 在此之上完成"体验与工程全面升级"：

1. **轻**：绿色便携、免安装、免管理员权限、整个文件夹可拷走即用；v5.0 延续 <20MB 包体红线。
2. **稳**：断线可恢复、升级可回滚、崩溃有日志、传输可续传——用户数据与工作现场永远不丢。
3. **安全可信**：凭据加密落盘、升级链路非对称签名验签、主机密钥严格校验——"安全"是可验证的工程事实，不是营销话术。

v5.0 的愿景一句话概括：**让中文用户在 Windows 上拥有一款"打开即用、断电不丢、升级不怕、界面不土"的 SSH 终端。**

### 1.3 目标用户画像

#### 画像 A：运维工程师（核心用户，占预期活跃用户 ~45%）

| 维度 | 描述 |
|---|---|
| 典型身份 | 企业 IT 运维 / IDC 机房运维 / 云平台值班运维 |
| 管理规模 | 20–500 台服务器，跨多个网络区域，常经跳板机访问内网 |
| 高频动作 | 批量巡检、日志排查、文件上传下载、端口转发访问内网管理台 |
| 痛点 | 现有工具（Xshell 收费、SecureCRT 昂贵） licensing 麻烦；跳板机链配置繁琐；断线后现场（cwd/scrollback）丢失要重敲命令 |
| v5.0 对应价值 | SOCKS5/HTTP 代理 + ProxyJump 跳板链、断线会话状态恢复、终端分屏、传输队列、known_hosts 管理界面 |
| 成功标准 | 一次配置跳板链后，双击会话即可经 A→B→C 直达目标机 |

#### 画像 B：开发人员（占预期活跃用户 ~35%）

| 维度 | 描述 |
|---|---|
| 典型身份 | 后端 / 全栈 / 数据工程师，日常 ssh 到开发/测试服务器与容器宿主机 |
| 高频动作 | 编辑远端文件、跑脚本、传代码包、看监控、敲常用命令 |
| 痛点 | 快捷命令不能带参数；大目录 SFTP 卡顿；界面老旧；换电脑配置搬不动 |
| v5.0 对应价值 | 脚本库升级（变量占位符 + 顺序宏）、WebGL 渲染、SFTP 管道化提速、v4 配置无损迁移、OpenSSH config 导入 |
| 成功标准 | 把 `~/.ssh/config` 一键导入后 5 分钟内完成全部日常会话搭建 |

#### 画像 C：轻度用户 / 学生 / 个人站长（占预期活跃用户 ~20%）

| 维度 | 描述 |
|---|---|
| 典型身份 | 个人站长、云服务器新手、计算机专业学生 |
| 高频动作 | 连 1–5 台服务器、传文件、改配置、重启服务 |
| 痛点 | 看不懂密钥/指纹/代理等概念；怕下到被篡改的安装包；界面英文多 |
| v5.0 对应价值 | 图形化 known_hosts 确认（人话解释）、签名验签的官方升级通道（防供应链投毒）、弱密码检测 + 密码生成器、四语言界面持续覆盖 |
| 成功标准 | 全程无文档辅助完成：下载 → 首次连接（指纹确认）→ 传一个文件 |

#### 画像 D：安全敏感型团队管理员（次要但战略用户）

| 维度 | 描述 |
|---|---|
| 典型身份 | 团队 Tech Lead / 安全审计人员，为团队选型并制定终端工具规范 |
| 痛点 | 需要可审计的升级链路、可导出的会话清单、硬件密钥支持 |
| v5.0 对应价值 | Ed25519 签名验签 + 官方发布机私钥管控、FIDO2(ed25519-sk) 支持、会话录制回放（审计留痕）、cargo audit 进 CI |
| 成功标准 | 能向安全部门出示：升级包签名验证机制说明 + 会话录制审计样例 |

### 1.4 版本核心目标（North Star）

| 目标 | 量化指标 |
|---|---|
| 体验升级 | 设置页/图标/主题完成设计系统化；用户满意度调研"界面现代"认可率 ≥ 70% |
| 安全加固 | 升级链路 100% Ed25519 验签覆盖；弱密码/弱算法 0 默认暴露 |
| 效率提升 | 千兆局域网 SFTP 吞吐 ≥ 100MB/s；冷启动 < 1s |
| 兼容承诺 | v4 用户升级成功率 ≥ 99.5%，配置/会话/密钥零丢失 |

### 2.2 逐项优劣与差异化

#### SecureCRT
- **优势**：企业级稳定性的标杆；脚本自动化（VBScript/Python）成熟；端口转发/跳板体验完整；20 年+ 商业打磨。
- **劣势**：价格昂贵；界面陈旧；无中文深度本地化；闭源不可审计。
- **EasySSH 差异化**：EasySSH 自 v1 起即以"SecureCRT 使用体验、零成本获取"为目标，v5.0 补齐脚本库（变量宏）后自动化能力对齐入门级需求，且免费 + 开源 + 绿色便携。

#### Xshell
- **优势**：个人版免费；中文体验优秀；与 Xftp 联动紧密；会话管理成熟。
- **劣势**：商用需付费；家庭/学校用途授权限制多；Xftp 分离安装增加管理成本；官网下载常被镜像劫持困扰（国内分发乱象）。
- **EasySSH 差异化**：单文件绿色包 + 官方站 https://EasySSH.CN 唯一下发渠道 + 签名验签 OTA，从分发源头杜绝"下载到二次打包木马版"的行业痛点。

#### WindTerm
- **优势**：免费开源；性能极强（自研终端引擎）；功能覆盖广（SSH/SFTP/Serial/Shell）。
- **劣势**：体积偏大（~80MB）；UI 信息密度过高对新手上手不友好；中文文档欠缺；更新节奏近年放缓。
- **EasySSH 差异化**：主打"轻而专"——10–20MB 体积、秒级冷启动、中文原生 UI；v5.0 通过 WebGL 渲染与 SFTP 管道化在性能上逼近 WindTerm，同时保持新手可用的信息密度。

#### Termius
- **优势**：跨平台（Win/Mac/Linux/iOS/Android）+ 云同步；设计感强；支持硬件密钥。
- **劣势**：核心功能（SFTP、Sync、SSH Config）锁在 Pro 订阅（$ 年费）；数据绑定其云服务，隐私顾虑；桌面端体积大。
- **EasySSH 差异化**：数据 100% 本地（config.json 随文件夹走，拷走即迁移），凭据 DPAPI + 主密码双保护，零订阅零云依赖——"你的服务器凭据只属于你"。

#### FinalShell
- **优势**：免费；服务器监控面板直观；SFTP 双栏易用；国内用户基数大。
- **劣势**：Java 技术栈导致内存占用高（空载 300MB+）；广告/推广弹窗历史；安装包体积大；安全审计性差（闭源 + 升级链路不透明）。
- **EasySSH 差异化**：Rust 原生实现，内存基线控制在 <80MB（见 §5.2）；系统监控 v4 已内置且无广告；开源可审计 + 签名升级链路，是安全敏感团队的唯一可选项。

### 2.3 差异化定位总结

1. **"绿色便携 + 免费开源 + 中文原生"** 三角组合，市场上无同位竞品。
2. **供应链安全**：Ed25519 签名 OTA + 自回滚，是全部免费竞品中独一份的工程承诺。
3. **轻量性能**：以 1/8 的体积提供 WindTerm 量级的性能（v5 管道化 + WebGL 后）。
4. **数据主权**：本地配置 + 可导出 + 无云绑定，对垒 Termius 的订阅云模式。

## 3. 功能规格说明书（M1–M4）

> 每项功能统一格式：**功能描述 → 用户故事 → 交互要点 → 验收标准（Given/When/Then）→ 优先级**。
> 优先级定义：P0 = 里程碑阻塞项，不做完不发版；P1 = 本里程碑应完成，可顺延至下一里程碑；P2 = 增强项，允许裁剪。

### 3.1 M1 地基（目标窗口：4 周）

#### F-M1-01 OTA 升级包 Ed25519 非对称签名

- **功能描述**：升级包由发布机持有的 Ed25519 私钥签名（对安装包字节流 SHA-256 摘要签名，签名随清单下发）；客户端内置公钥（编译期嵌入二进制）验签，验签失败拒绝安装。取代现有"共享对称密钥 + HMAC"的单一防线，消除"客户端即密钥持有者"的伪造风险。
- **用户故事**：
  - 作为安全敏感的用户，我希望升级包经过非对称签名验证，以便即使官方服务器被入侵、我也不会安装未经发布机私钥签名的恶意包。
  - 作为发布工程师，我希望私钥只存在于发布机，以便开发机失窃也无法伪造升级包。
- **交互要点**：
  - 验签失败时横幅显示"升级包签名校验失败，已中止安装"，并提供官网手动下载链接与该包 SHA-256 供人工比对。
  - 设置页「检查更新」详情区展示当前升级通道的签名公钥指纹（前 16 位）。
- **验收标准**：
  - Given 一份官方发布机签名的升级包，When 客户端下载并执行验签，Then 验签通过且允许进入替换流程。
  - Given 篡改任意 1 字节后的升级包，When 验签，Then 拒绝安装并在横幅展示失败原因，`updates/` 目录不落地可执行文件。
  - Given 伪造清单（签名字段替换为攻击者自签），When 验签，Then 拒绝并记录安全事件日志（升级日志文件）。
  - Given 客户端二进制，When 提取内嵌公钥指纹，Then 与官网公示指纹一致。
- **优先级**：P0

#### F-M1-02 升级自回滚（健康自检失败自动回滚）

- **功能描述**：升级后新版以 `--upgraded` 启动时执行健康自检（窗口创建成功、前端首帧渲染、核心命令 ping 通、配置读写正常），自检通过后删除 `.bak`；失败则以 `.bak` 旧版回滚启动并提示用户。延续 v4 的"旧 exe 改名 .bak → 新版顶替 → 分离启动 --upgraded"机制，补齐"新版坏了自动回老版"闭环。
- **用户故事**：作为普通用户，我希望升级后如果新版无法正常启动，软件能自动回滚到旧版本，以便我的工作不因一次失败的升级而中断。
- **交互要点**：回滚发生时启动画面显示"新版健康检查未通过，已自动恢复旧版本 vX.Y.Z"；设置页提供「上报本次回滚」（匿名，含版本对与失败阶段）。
- **验收标准**：
  - Given 新版正常启动且自检全部通过，When 自检完成，Then `.bak` 在 60s 内被删除。
  - Given 人为构造前端初始化失败的新版（测试专用故障注入开关），When 以 `--upgraded` 启动，Then 30s 内回滚启动 `.bak` 旧版，且用户可见回滚提示。
  - Given 回滚执行中旧 exe 被占用，When 重试 3 次仍失败，Then 保留 `.bak` 并在下次启动时重试清理，绝不删除用户唯一可用的程序文件。
- **优先级**：P0

#### F-M1-03 Argon2id 默认密钥派生

- **功能描述**：主密码派生从 PBKDF2-SHA256 600k（wrap:v3）升级为 Argon2id（m=64MiB, t=3, p=1，wrap:v4）作为新写入默认；v1/v2/v3 全兼容可解，首次解锁后透明迁移。v4.3.1 已引入 Argon2id，本项将其定为唯一默认并补齐强制迁移与降级防护。
- **用户故事**：作为启用主密码的用户，我希望我的口令使用抗 GPU 暴力破解的现代算法派生密钥，以便配置文件被拷走时口令难以被离线破解。
- **交互要点**：无感知；设置页主密码卡片显示当前"加密格式：Argon2id (wrap:v4)"。
- **验收标准**：
  - Given 全新启用主密码，When 查看 config.key.enc 头部，Then 标记为 wrap:v4。
  - Given wrap:v1/v2/v3 旧文件，When 解锁，Then 解密成功且解锁成功后自动重写为 v4。
  - Given Argon2id 派生单次耗时，When 在参考机型（4 核/8GB）实测，Then 200ms–1000ms 区间内。
- **优先级**：P0

#### F-M1-04 renderer.js 模块化拆分起步

- **功能描述**：将 ui/renderer.js（约 2081 行单体）按职责拆分为 ES Module：`core/`（config、i18n、event-bus）、`tabs/`、`term/`、`sftp/`、`forward/`、`settings/`、`update/`，经 Vite 构建输出单入口 bundle；零框架策略不变。M1 仅完成骨架与 2–3 个模块的物理拆分（sftp、update、settings），后续里程碑持续迁出。
- **用户故事**：作为开发者，我希望前端代码模块化，以便多人协作时不冲突、缺陷定位可按模块归因。
- **交互要点**：无用户可见变化（行为完全等价）。
- **验收标准**：
  - Given 拆分后构建产物，When 运行回归用例（连接/传文件/升级检查/设置切换共 20 条冒烟），Then 全部通过且无行为差异。
  - Given renderer.js，When M1 结束，Then 主文件 ≤ 600 行，新增模块均有单文件职责边界注释与导出清单。
  - Given 构建管线，When `pnpm build`，Then 产出带内容哈希文件名的 bundle 且 CSP `script-src 'self'` 保持有效。
- **优先级**：P0

### 3.2 M2 效率健壮（目标窗口：5 周）

#### F-M2-01 SFTP 传输管道化

- **功能描述**：大文件读写请求流水线化：并发在途请求 8–16（可配）、调大 russh-sftp 窗口（建议 2MB read window / 256KB packet）、可选 zstd 压缩（默认关，仅压缩收益大的文本类内容推荐开启）。
- **用户故事**：作为运维工程师，我希望千兆内网传大文件能跑满带宽，以便镜像/备份任务从小时级降到分钟级。
- **交互要点**：设置 → 传输：并发深度（4/8/16）、zstd 开关；传输队列详情显示当前在途请求数与实时速率曲线。
- **验收标准**：
  - Given 千兆局域网 + 本地 NVMe 服务器，When 下载 1GB 单文件，Then 平均吞吐 ≥ 100MB/s（v4 基线 ≥ 3 倍）。
  - Given 高延迟链路（模拟 100ms RTT），When 相同文件，Then 吞吐相对串行基线提升 ≥ 3 倍。
  - Given zstd 开启且传输文本日志类文件，When 完成后比对源与目标 SHA-256，Then 完全一致（压缩不损正确性）；二进制文件自动禁用压缩。
- **优先级**：P0

#### F-M2-02 SFTP 断点续传（上传 + 下载全量）

- **用户故事**：作为用户，我希望 10GB 文件传输中途断线后重连能从断点继续，以便不必前功尽弃。
- **交互要点**：传输队列中断任务显示「▶ 续传」与已传百分比；续传前校验远端文件大小 ≥ 本地 offset，不满足则提示"远端文件已变化，建议重传"。
- **验收标准**：
  - Given 500MB 下载在 40% 时断网，When 网络恢复点「续传」，Then 从 ~200MB 处继续且最终文件 SHA-256 与源一致。

#### F-S-04 cargo audit 进构建

- **功能描述**：CI 增加 `cargo audit`（RustSec advisory 库扫描）步骤；发现高危漏洞 CVE 时构建失败（允许白名单豁免 + 豁免到期日强制复审）。
- **验收标准**：
  - Given 依赖树含已知高危 RUSTSEC 告警，When CI 运行，Then 构建失败并输出告警详情与修复建议。
  - Given 豁免条目，When 超过豁免到期日，Then 构建重新失败强制复审。
- **优先级**：P0

#### F-S-05 弱密码检测 + 密码生成器

- **功能描述**：新建/编辑会话保存密码时执行弱密码检测（长度 <8、纯数字、键盘序列、常见字典 TOP1000），命中给非阻断警告；连接与表单内提供密码生成器（长度/字符集可配）。
- **用户故事**：作为轻度用户，我希望设置弱密码时被提醒、需要强密码时一键生成，以便降低服务器被爆破的风险。
- **验收标准**：
  - Given 密码 "123456"，When 保存会话，Then 显示黄色警告（可继续保存）。
  - Given 生成器默认配置（16 位，含大小写数字符号），When 生成，Then 每次结果满足字符集且长度精确。
  - Given 密码强度评估，When 本地执行，Then 不产生任何网络请求（纯本地实现）。
- **优先级**：P1

## 4. 安全需求规格

### 4.1 威胁模型总览

| 编号 | 威胁场景 | 攻击面 | 受影响资产 | 严重级 |
|---|---|---|---|---|
| T1 | 供应链投毒：升级包被篡改/服务器被入侵后下发恶意包 | OTA 检测/下载/安装链路 | 用户主机 | **Critical** |

| T3 | 离线口令爆破：攻击者离线穷举主密码 | config.key.enc | 全部凭据 | High |
| T4 | 中间人攻击：伪造 SSH 服务器/主机密钥替换 | SSH 握手 | 会话数据、凭据 | High |
| T5 | 弱算法协商降级（SHA-1/CBC 类） | SSH 算法协商 | 会话机密性 | Medium |

### 4.2 加密

| 需求编号 | 需求 | 对策与实现要求 | 验证方式 |
|---|---|---|---|
| S-ENC-01 | 会话密码/私钥口令落盘必须加密 | 延续 AES-256-GCM（`enc:v1:<iv>:<tag>:<密文>`），密钥经 config.key + DPAPI（ESSHDPAPI1）双保护，绝不允许明文字段落盘 | 代码审查 + grep 全字段扫描 SECRET_FIELDS 覆盖清单 |
| S-ENC-02 | 主密码派生使用 Argon2id | wrap:v4（m=64MiB, t=3, p=1）；v1–v3 兼容读、首次解锁透明迁移；禁止降级写回旧格式 | 单测 + 真实文件迁移用例 |
| S-ENC-03 | SECRET_FIELDS 扩面 | password/passphrase 之外：代理凭据、脚本库敏感变量、（若存库）私钥内容全部纳入加密字段 | 导出 JSON diff 检查无任何密文外字段含敏感样本 |
| S-ENC-04 | 随机数来源 | 全部密钥/nonce 使用 OS CSPRNG（`getrandom`），禁止自研 PRNG | 代码审查 |
| S-ENC-05 | 会话导出永不携带密文密码 | 导出前强制剔除全部 SECRET_FIELDS，含嵌套结构 | 单测：构造含密文样本导出后断言不存在 |

### 4.3 认证与主机信任

| 需求编号 | 需求 | 对策 | 验证方式 |
|---|---|---|---|
| S-AUTH-01 | 主机密钥严格校验 | TOFU 首次确认 + 变更高危告警 + 管理界面审计（F-S-01）；拒绝默认信任变更 | 集成测试：模拟换 key 重连必弹告警 |
| S-AUTH-02 | 算法白名单 | 默认禁用 ssh-rsa(SHA-1)、CBC 模式、弱 KEX；「兼容模式」开关单独入口 + 明确风险文案 | 集成测试：对仅支持弱算法的 sshd 连接失败且提示兼容开关 |
| S-AUTH-03 | FIDO2 硬件密钥 | ed25519-sk 生成与认证（F-S-02），触摸确认必经 | 真机用例 |
| S-AUTH-04 | 认证失败信息不泄露敏感值 | 错误回显禁止包含密码/口令明文（v4.2.5 曾有的参数回显诊断必须脱敏） | 单测断言错误串不含输入敏感值 |
| S-AUTH-05 | 只读锁定 | 会话可切换只读（防误操作生产机），只读态输入全部丢弃并提示 | 冒烟用例 |

## 6. 兼容性与迁移规范

### 6.1 兼容承诺（对外口径）

1. **v4 配置/会话/密钥无损迁移**：config.json / config.key(.enc) / keys/ 目录 / 分组 / 备注 / 颜色 / 端口转发配置 / 快捷命令，升级后全部可用，零手工操作。
2. **升级通道格式向后兼容一个版本**：v5 清单/信封格式变更时，服务端保留 v4 兼容通道；v5 客户端可解析 v4 格式清单。
3. **主密码协议兼容**：wrap:v1/v2/v3/v4 全可解；迁移只升不降。
4. **known_hosts/指纹兼容**：v4 存于 config.json 的指纹自动迁移至 v5 主机密钥库，语义不变（TOFU 记录保留原信任时间）。

### 6.2 v4 → v5 配置迁移步骤（实现规范）

| 步骤 | 动作 | 失败处理 |
|---|---|---|
| 1 | 启动时检测 config.json `schema_version`（v4 隐含 "4.x"）；无字段按 v4 处理 | 解析失败 → 走 bak.1~5 回退链（v4 既有） |
| 2 | 原地迁移：写 config.json.v5-tmp → 原子替换；新增 `schema_version: "5.0"`、`hostkeys`（指纹库）、`transfer`（并发/压缩）、`proxy`（会话级）字段，缺省补默认值 | 迁移失败保留原文件并报错，绝不半写（原子写保证） |
| 3 | 指纹数据迁入 hostkeys 表，逐条携带原记录 | 单条损坏跳过并记录，不阻断整体 |
| 4 | config.key(.enc) 不迁移、原地沿用（wrap 协议不变，首次解锁后按 S-ENC-02 透明升 v4） | 解密失败 → 明确报错 + 处理指引，不静默重置 |
| 5 | 迁移完成标记写入；后续启动跳过迁移 | — |

### 6.3 回滚路径

| 场景 | 回滚机制 |
|---|---|
| v5 OTA 安装后新版不健康 | `--upgraded` 自检失败自动回滚 .bak（F-M1-02）；回滚后 v5 新增字段（hostkeys 等）对 v4 是多余键，v4 忽略未知字段，配置可逆 |
| 用户手动降级 v4 | v4.3.x 可直接读取带 `schema_version:5.0` 的 config.json（忽略未知字段）——**必须用 v4.3.11+ 实测验证**；不满足时提供「导出会话 JSON（v4 格式）」逃生功能 |
| 迁移中途崩溃 | 原子写保证旧文件完好；重启重走迁移 |
| 主密码 wrap 升级后降级 | v4.3.1+ 支持 Argon2id（wrap:v3），与 v5 的 v4 格式（编号避免冲突，如 wrap:v5 或按 m/t/p 参数自描述）互通——实现前须先冻结格式编号设计并写入本文档附录 |

> ⚠️ **实现注意**：v4.3.1 已将 Argon2id 格式标记为 wrap:v3，v5 的"Argon2id 默认"应沿用/演进该格式编号而非新造 v4 编号，避免与 v4.x 版本号混淆。格式编号分配表须在本手册附录维护，任何格式变更先改表。

## 附录 C：术语表

| 术语 | 释义 |
|---|---|
| OTA | Over-The-Air，应用内在线升级通道（检测→下载→替换→自检） |
| TOFU | Trust On First Use，首次连接展示指纹由用户确认并信任的主机密钥策略 |
| ProxyJump | OpenSSH 的跳板机机制：经中间主机中转 TCP 连接到达目标主机 |
| SOCKS5/HTTP CONNECT | 两种本地代理协议，v5 用于会话前置代理（经代理服务器建立到 SSH 服务器的 TCP） |
| Argon2id | 内存困难型口令哈希算法（2015 密码哈希竞赛优胜者），抗 GPU/ASIC 离线爆破 |
| wrap 格式 | config.key.enc 的密钥包裹格式标记（v4 系列为 v1=PBKDF2-100k / v2=PBKDF2-600k / v3=Argon2id） |
| DPAPI | Windows Data Protection API，绑定当前用户的操作系统级数据加密（EasySSH 以 ESSHDPAPI1 格式使用） |
| SFTP 管道化 | 在单连接上并发发出多个读写请求而不逐个等待应答，以提升高延迟链路吞吐 |
| scrollback | 终端回滚缓冲区（历史输出行） |
| Design Token | 设计系统中的命名设计变量（颜色/间距/字号等），主题派生的最小单位 |
| asciicast v2 | asciinema 会话录制格式（JSON 行：时间戳 + 输出数据） |
| webroot 原子部署 | 官网发布目录按版本落盘 + 符号链接原子切换的部署方式，切换瞬间无 404 窗口 |
| 冒烟门禁 | 发版流水线中的强制自测关卡（版本校验→启动→OTA 端到端），任一步失败禁止发布 |
| RUSTSEC | Rust 生态安全公告数据库，cargo audit 依据其扫描依赖漏洞 |
