# 冒烟门禁（v5(M2)/F-P-02）

发版脚本 `scripts/push-release.ps1` 在**上传到发布机之前**强制执行冒烟门禁，位于"交付目录就绪"与"上传 incoming"之间（步骤 1.5）。任一门禁失败即中止发布，原因写入 `release-log.md`（与 v5(M1) 对接发布执行记录日志规范一致）。

## 门禁项

| # | 门禁项 | 判定 | 失败原因示例 |
|---|--------|------|--------------|
| 1 | 产物存在性 | `dist-v4\EasySSH-<版本>-portable.exe` 存在 | 缺少产物（先跑构建脚本） |
| 2 | 版本一致性 | exe `FileVersion` == 传入 `-Version` | FileVersion(5.0.0-alpha.1) 与配置版本不一致 |
| 3 | 启动冒烟 | 分离启动便携版 → **8 秒内进程存活** → `taskkill` 强制结束 | 进程 8 秒内退出 → 360 疑似拦截 |

## 360 拦截说明

启动冒烟失败的典型原因是 360 安全卫士拦截了未信任的新构建 exe。处理：将 `dist-v4` 目录（dist-v4 已在开发机加白名单）加入 360 信任区后重跑门禁。门禁失败信息中会明确提示"360 疑似拦截"。

## 手动绕过（限应急）

```
powershell -File scripts\push-release.ps1 -Version 5.0.0-alpha.1 -SkipSmoke
```

- `-SkipSmoke` 传递给 `scripts/smoke-gate.ps1`，跳过全部三项门禁。
- 绕过会在 `release-log.md` 留痕：`冒烟门禁: 已跳过 — 原因: 调用方显式指定 skip-smoke（应急发布）`。
- **仅限应急发布**；正常发版禁止使用。

## 执行记录格式（与 M1 一致）

```
- 2026-11-03 09:30:00 [dev-machine(dsh)] v5.0.0-alpha.1 冒烟门禁: 通过

```

## 独立运行门禁（调试用）

```
powershell -File scripts\smoke-gate.ps1 -Version 5.0.0-alpha.1 [-Dist <产物目录>] [-SkipSmoke]
```
