迁移概览

EasySSH 内置存量会话一键导入，支持直接读取本机 Xshell 会话、PuTTY 注册表会话、Termius 导出 JSON 与 OpenSSH config 文件；配合 JSON 导入导出（自动脱敏）与 Ed25519 密钥生成 / 安装 / 诊断，绝大多数迁移场景无需手工逐条抄录。

原工具EasySSH 导入方式凭据是否迁移
Xshell自动读取本机会话管理器 .xsh（兼容 NetSarang 多版本目录）主机/端口/用户名，密码不迁移
PuTTY自动读取注册表会话（仅 SSH）主机/端口/用户名，密码不迁移
Termius导入 Termius 导出的 JSON（凭据按 id 解析用户名）主机/端口/用户名，密码不迁移
OpenSSH导入 ~/.ssh/config 文件主机/端口/用户名/跳板链，密码不迁移

导入统一按主机 + 端口 + 用户名去重，并沿用与 JSON 导入相同的脱敏规则（不含密码），自动归入对应来源分组。首次连接时重新输入一次密码即可。

一、会话批量导入步骤

导入入口位于设置 / 侧栏「外部」按钮组（与「新建分组 / 导出 / 导入」同组）。四个来源共用同一套流程：

  1. 打开导入入口：启动 EasySSH，在左侧会话列表底部找到「外部」按钮组，点击进入外部会话导入面板。
  2. 选择来源：在面板中选择要导入的工具类型——Xshell / PuTTY / Termius / OpenSSH config。
  3. 提供数据源（按来源不同）：
    • Xshell：自动扫描本机 NetSarang 会话目录（多版本目录均兼容），列出可用 .xsh 会话；若安装路径特殊，可手动指定会话目录。
    • PuTTY：自动读取注册表中的 PuTTY 会话（仅 SSH 类型，经隐藏窗口 reg query 读取，无新增依赖）。
    • Termius：先在 Termius 中使用其「导出」功能导出 JSON 文件，再在导入面板中选择该文件；用户名按凭据 id 自动解析。
    • OpenSSH config：选择 ~/.ssh/config 文件（支持手动指定路径），通配符 Host 块自动跳过。
  4. 预览并执行导入：确认待导入会话列表后点击导入；重复的会话（主机+端口+用户名相同）自动跳过并提示跳过数量。
  5. 补录凭据：导入的会话不含密码。首次连接时输入密码，或按需改用私钥认证（见第二、五节）。
提示：导入的会话自动归入对应来源分组（如「Xshell」「PuTTY」），方便迁移后逐个验证、整理到自己的分组里。

二、PuTTY .ppk 私钥迁移

PuTTY 使用自己的 .ppk 私钥格式，EasySSH 使用标准 OpenSSH 格式私钥。迁移方法：

方法 A：PuTTYgen 转换（通用，任何版本可用）

  1. 打开 PuTTY 自带的 PuTTYgen（开始菜单 → PuTTY → PuTTYgen）。
  2. 点击 Load，选择你现有的 .ppk 私钥文件（若密钥带口令，会先要求输入口令）。
  3. 菜单栏选择 Conversions → Export OpenSSH key（注意选择「Export OpenSSH key」，即新版格式，而非 "for SSH-1"）。
  4. 选择保存路径（如 keys\myserver.openssh），保存。
  5. 在 EasySSH 会话编辑中把认证方式设为「私钥文件」，选择刚导出的 OpenSSH 格式私钥。

方法 B：.ppk 直接导入（v5.2.0 起）

EasySSH v5.2.0 起支持 .ppk 直接导入：在会话编辑中选择私钥文件时直接选 .ppk 文件即可。

  • 未加密密钥（无口令）：自动转换为 OpenSSH 格式，无需任何手工步骤。
  • 带口令的 ppk：请先在 PuTTYgen 中去掉口令（加载密钥后 Key passphrase 留空并 Save private key），或按方法 A 导出为 OpenSSH 格式后再导入。
提示：迁移后可删除原 .ppk 前先在 PuTTYgen 里确认新私钥可正常登录目标服务器；EasySSH 的密钥工具还能对当前已连服务器一键安装公钥并设置 700/600 权限。

三、OpenSSH config（~/.ssh/config）导入说明

如果你在 Linux/macOS 或 Windows 上维护 ~/.ssh/config，可以直接把它导入 EasySSH：

  • 支持的指令：Host、HostName、Port、User、ProxyJump（转换为 EasySSH 的跳板链，见下一节）。
  • 自动跳过：通配符 Host 块（如 Host *.corp）不生成会话；IdentityFile、ProxyCommand 等其他指令当前不参与转换。
  • 去重：与主机+端口+用户名相同的已有会话自动跳过。
  • 操作：设置 / 侧栏「外部」按钮组 → 选择「OpenSSH config」→ 指定 config 文件路径 → 导入。
注意：config 中的跳板依赖（ProxyJump）会指向一个目标会话名，请确保对应名字的会话存在于 EasySSH 中（通常是先导入全部会话，跳板链即自动接上）。

四、跳板机（ProxyJump）配置示例

EasySSH 支持把已存会话设为另一个会话的跳板，最多 3 级，且逐级复用该跳已存会话的凭据——跳板机自己怎么登录，就复用它已保存的登录方式（密码或私钥），不需要重复录入。

示例场景

目标：从本机经跳板机 bastion 连接内网服务器 app01。对应 OpenSSH 写法是：

Host app01
    HostName 10.0.1.20
    User deploy
    Port 22
    ProxyJump bastion

在 EasySSH 中配置

  1. 确保跳板会话已存在：先在 EasySSH 中保存名为「bastion」的会话（bastion 公司的公网地址、跳板账号，密码或私钥均可），并能正常登录。
  2. 编辑目标会话：打开或新建「app01」会话（10.0.1.20 / 22 / deploy）。
  3. 配置跳板链：在会话编辑的「代理与跳板」区域选择 ProxyJump，跳板链第一级选择已存会话「bastion」。EasySSH 会按「先连跳板、再借道转发到目标」的顺序建立连接。
  4. 保存并连接：连接时 EasySSH 自动复用「bastion」已存会话的凭据登录跳板，再直连 app01。转发与代理配置随会话持久化，断线重连自动恢复。

如需两级/三级链路（如 本机 → bastion → inner-jump → db01），在跳板链中按顺序依次追加已存会话即可，最多 3 级。

五、私钥文件权限注意事项

  • Windows：私钥文件（keys/ 目录下的文件以及迁移进来的 OpenSSH 私钥）不要对所有人开放可读。建议右键文件 → 属性 → 安全，移除「Everyone / Users」的读取权限，仅保留当前用户；不要把私钥放在共享目录或网盘同步目录里。
  • 拷贝携带：EasySSH 为绿色便携设计，私钥随 exe 同目录的 keys/ 携带；用 U 盘/移动盘搬运时，注意目标机器上的权限继承，拷贝后重新收紧 ACL。
  • 不要用公开口令：迁移自 PuTTYgen 的未加密私钥没有任何口令保护，任何拿到文件的人都能用它登录服务器。重要服务器建议在 EasySSH 中重新生成 Ed25519 密钥对，并用「安装到当前已连服务器」一键部署后废弃旧钥匙。
  • config.json 明文提示：勾选「保存会话」时密码明文保存在本机 config.json 中，请仅在可信环境使用。

六、常见迁移问题 FAQ

Q1：导入后为什么没有密码？

导入统一走脱敏规则，不迁移任何密码（与 JSON 导入导出同一套规则）。首次连接输入一次密码即可；如需免密，推荐用密钥认证（见第二节与第五节）。

Q2：PuTTY 导入列表为空？

PuTTY 会话保存在注册表中，EasySSH 只读取 SSH 类型的会话（Telnet/Serial 会话不导入）。确认会话是在 PuTTY 本机保存过（而非仅用 Open Session 临时打开），并以安装 PuTTY 的同一 Windows 用户运行 EasySSH。

Q3：OpenSSH config 导入后部分会话缺失？

通配符 Host 块（如 Host *.corp）会被自动跳过；只支持 Host/HostName/Port/User/ProxyJump。含通配符匹配规则的主机请手工新建会话。

Q4：带口令的 .ppk 导入失败？

EasySSH 可自动转换未加密的 .ppk（v5.2.0 起）。带口令的 ppk 请先在 PuTTYgen 中去掉口令，或用 Conversions → Export OpenSSH key 导出为 OpenSSH 格式后再选入。

Q5：跳板链连接失败怎么排查？

先单独连接跳板会话确认其凭据可用；再检查目标会话的跳板链中选择的会话名是否正确。跳板最多 3 级，且每级都复用该已存会话自己的凭据——跳板换了密码请同步更新跳板会话本身。
