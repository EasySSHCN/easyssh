# How to Report a Security Vulnerability

Do not report security vulnerabilities through public issues, to avoid exploitation before a fix is released.
Reporting channel: the in-app "💬 Feedback" feature
Open EasySSH and click the "💬 Feedback" button on the toolbar: choose "Problem Report" as the type, mention "Security vulnerability report" in the message, and describe the vulnerability type, impact, and reproduction steps; be sure to include contact information (email / GitHub / WeChat, etc.) so we can reach you about the fix and credit.

Feedback is transmitted through an AES-256-GCM encrypted envelope (the same family of encryption protocol as the online updater, with time-bound signatures to prevent replay), and can only be viewed by administrators in the website backend — it is never displayed publicly. Only content that has been fixed and is safe to disclose will appear in the download page's "Top 10 Featured Feedback".

Please try to include in your report:

  1. The vulnerability type and impact description (exploitable scenarios)
  2. Reproduction steps or a proof of concept (PoC; you may mark it "admin-only visibility")
  3. The affected EasySSH version (visible under "Settings → About" in the app)
  4. Your preferred form of credit (or request anonymity, noted in the feedback)

# Update Chain Signatures (Ed25519)

Since v5.0, the online update manifest uses Ed25519 asymmetric signatures: signed with the release machine's private key and verified by a public key embedded in the client. Manifests that fail verification are rejected from installation — even if the update encryption master key leaks, an attacker cannot forge an update package.

# Security Notes for Users

  • Password storage: session passwords are stored in config.json in the same directory as the exe, in plaintext. Do not check "Save session" in untrusted environments.
  • Code signing: the exe is not code-signed at present, so SmartScreen will prompt once on first run — just click "Run anyway". Always download from the official site easyssh.cn and verify the artifact's integrity with the sha256 provided on the download page.
  • Data portability: sessions, settings, and keys (the keys/ directory) are all stored next to the exe and travel with the folder. Keep that directory safe to avoid leaking private keys and passwords.
  • Debug log: %TEMP%\easyssh-debug.log may contain connection diagnostics; check it for sensitive content before submitting an issue.
