FAQ

15 questions · kept in sync with the repository docs source (docs-src/faq.md)

1. SmartScreen says "Windows protected your PC" on first run — is it safe?

The EasySSH exe is not code-signed, so Windows SmartScreen shows a one-time prompt for unsigned programs. After confirming the file comes from the official site easyssh.cn and its sha256 matches the one on the download page, click "More info" → "Run anyway"; it won't prompt again afterwards.

2. What should I do when Chinese text is garbled in the terminal?

In the Settings Center, change the encoding to GBK or GB18030 (matching the server's actual encoding). Note: the encoding setting only takes effect for newly created connections — disconnect and reconnect after changing it.

3. Connection reports "Cannot parse privateKey: Unsupported key format"

You may be using a PKCS#8 private key generated by v2.3.0/2.3.1. Please upgrade to v2.3.2 or later: new keys are generated in the standard OpenSSH format, and at connect time old PKCS#8 keys are converted automatically to a parseable format — old keys do not need to be regenerated.

4. How do I uninstall EasySSH?

EasySSH is a portable app and requires no uninstaller: just delete the folder containing the exe. Sessions, settings (config.json) and keys (keys/) all live in that folder, so deleting it removes everything. If you are worried about password leakage, clear the saved password from the "Save session" record before deleting.

5. Is EasySSH free? Is it open source?

Completely free and open source under the MIT License, with all source code public — free to use, modify and distribute. The tech stack (Rust, Tauri 2, russh, xterm.js) is entirely open-source components.

6. Where is my password stored, and is it safe?

It is stored in config.json next to the exe, in plain text, and travels with the folder. Use it only in trusted environments; don't check "Save session" on untrusted machines such as public computers.

7. After checking "Save session", connections always use the old password?

The saved session password overrides the password you type in on the next connection. If the server password has changed, delete or edit that session record, then reconnect and save the new password.

8. How do I reconnect after a session drops?

The tab stays open; press Enter in the terminal to reconnect automatically. If reconnection fails, press Enter again to retry.

9. Do my configuration and sessions survive switching computers or reinstalling the OS?

Yes. Sessions, settings and keys all travel with the folder containing the exe — copy the whole folder to the new computer and keep using it, with no import/export steps needed.

10. Line endings are wrong / text is garbled after SFTP-transferring a text file to Windows?

Use the "Text conversion" transfer mode: on download the server encoding is converted to UTF-8 with CRLF line endings, and on upload the reverse conversion is applied. Binary mode transfers as-is with no conversion — always use binary mode for programs/archives.

11. How do I install the generated key onto a server?

Two ways: ① copy the public key shown in the interface and manually append it to the server's ~/.ssh/authorized_keys; ② in a session already connected by password, click "Install to the current connected server" to write it automatically with proper permissions set (700/600); afterwards you can switch to key-based login.

12. "File in use" error preventing startup?

A single-instance lock has prevented leftover processes since v1.4.1. If it still happens, open Task Manager and end the leftover EasySSH process before starting again.

13. Do I need to migrate my configuration when upgrading from v4 to v5?

No. v5 is fully compatible with v4 configuration, sessions and the master password; after an online upgrade or an in-place install, all data carries over automatically. Upgrade packages are verified with Ed25519 signatures, and failed upgrades automatically roll back to the previous version.

14. How do I use v5's terminal split view and command palette?

The toolbar "Split" button toggles single / left-right / top-bottom / quad layouts; drag dividers to adjust proportions. The global command palette opens with Ctrl+Shift+P — type characters or initials to filter sessions and actions.

15. Why does the "server host fingerprint" confirmation appear the first time I connect to a server?

This is a security mechanism against man-in-the-middle attacks (TOFU): on first connection the server fingerprint is shown for you to verify; click "Trust and save" and it is remembered permanently, verified automatically on later connections. If the prompt keeps reappearing on an already-trusted server, please report it to us.

Portable SSH/SFTP terminal for Windows. A lightweight, self-developed implementation inspired by the SecureCRT experience, with 100% original code.
