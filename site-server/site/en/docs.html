User Guide

EasySSH is a portable SSH/SFTP terminal for Windows, designed with the SecureCRT user experience in mind — no installation required, carry it with you in a folder.

1. Download & Installation

EasySSH is a portable application — no installation required — available in two forms:

  • Single-file portable exe: download EasySSH-<version>.exe and run it directly. Sessions and configuration are stored in the same directory as the exe, so the whole folder can be copied to a USB drive or another computer.
  • zip package: download EasySSH-<version>-win32-x64-portable.zip, extract it to any directory and run the exe inside. Ideal if you prefer to keep the program and its data in a fixed folder.
Tip: Always download from the official site easyssh.cn, and verify file integrity with the sha256 value provided on the download page.

2. First Run & SmartScreen Prompt

The exe is currently not code-signed, so on first run Windows Defender SmartScreen shows a "Windows protected your PC" prompt. This is expected:

  1. Click "More info" in the SmartScreen dialog;
  2. Click "Run anyway".

This prompt appears only once, on the first run. If a file obtained from an unofficial source shows this prompt, verify the sha256 first.

3. Making Connections & Sessions

Connection parameters: click New Session, fill in the host address, port (default 22) and username, then choose an authentication method:

  • Password authentication: enter the server password directly. You may check "Save session" to store the password with the session (note: the password is stored in plain text in a local config file — do not check this on untrusted machines).
  • Private key authentication: select a local private key file (see Section 7, Key Tools).
  • keyboard-interactive auto-fit: uses the standard tryKeyboard + keyboard-interactive authentication flow; most servers with interactive authentication enabled work automatically.

Session management: sessions are deduplicated and saved by host + port + username; duplicate records are cleaned up automatically at startup. Since v2.2.0, all sessions and settings are stored in a single config.json in the same directory as the exe (old sessions.json / settings.json are migrated automatically), and travel with the folder.

4. Terminal Operations

  • Multiple tabs: open several SSH session tabs in one window.
  • Auto reconnect: after a disconnect the tab stays open; press Enter in the terminal to reconnect automatically — press Enter again to retry if it fails.
  • Scrollback: 5000-line scrollback to review history output.
  • keepalive: built-in keepalive keeps long-lived connections alive.
  • Window resizing: the terminal adjusts rows and columns automatically with the window size, with 256-color support.
  • Connection status: while connecting, the status bar shows a live countdown (timeout cap 30 seconds); on failure it shows the first error line plus troubleshooting hints for auth failure / timeout / connection refused.

5. SFTP File Transfer

Built-in SFTP transfer panel: browse remote directories (parent directory and path jumps supported), upload (multi-select), and download (double-click a remote file).

Transfer modes and encoding — selectable when transferring:

  • Binary (as-is, recommended): transfers bytes as-is; suitable for programs, archives, images and all other non-text files.
  • Text conversion: converts using the encoding chosen in the Settings Center — great for exchanging text/script files between Windows and Chinese Linux servers:
    • Download: server encoding → UTF-8, line endings normalized to CRLF;
    • Upload: UTF-8 → server encoding, line endings normalized to LF;
    • Temporary files used during conversion are cleaned up automatically.
Note: if text shows garbled Chinese after transfer, make sure the Settings Center encoding matches the server's actual encoding (GBK-family encodings usually fix garbled text on Chinese servers).

6. Quick Command Bar

  • Define frequently used commands as buttons (e.g. systemctl status nginx, df -h);
  • Clicking a button sends the command to the current terminal;
  • Add and remove commands as needed; theme skins also cover the quick command bar.

7. Key Tools

When the authentication method is "Private key file", a key tools panel appears:

  1. One-click key generation: generates an Ed25519 key pair locally. Since v2.3.2, private keys use the standard OpenSSH format (openssh-key-v1, unencrypted), usable directly by ssh2; the private key path is filled in automatically after generation.
  2. Public key upload: the public key is shown in the interface so you can copy and manually append it to the server's ~/.ssh/authorized_keys.
  3. Install to the current connected server: in a session already connected by password, one click writes the public key to the server (idempotent, automatically sets directory 700 / file 600 permissions); afterwards you can switch to key-based login.
  4. Automatic legacy key compatibility: since v2.3.2, PKCS#8 private keys generated by older versions (v2.3.0/2.3.1) (Ed25519/RSA/EC) are automatically converted to a parseable format at connect time — no need to regenerate old keys.

Keys are stored in the keys/ directory next to the exe and travel with the folder — keep them safe.

8. Settings Center

  • Font: 5 choices; font size: custom terminal font size.
  • Encoding: UTF-8 / GBK / GB18030 / Big5. GBK-family encodings usually fix garbled text on Chinese servers.
  • Skins: Dracula / Pure Black / Solarized / Light / Matrix — 5 color schemes in total. Since v2.2.0, skins cover the entire application UI (sidebar, toolbar, dialogs, status bar, quick command bar); the custom-drawn title bar colors follow the skin as well.
Note: encoding changes take effect for newly created connections; already-connected sessions are not affected.

9. config.json Portability

  • Sessions and settings are stored together in config.json next to the exe; old files are migrated automatically — no manual steps needed.
  • Keys are stored in the sibling keys/ directory.
  • Migration/backup: copy the entire exe folder to take all configuration, sessions and keys with you.
  • Security note: session passwords in config.json are stored in plain text — use it only in trusted environments.

10. Auto Reconnect

  • After the server exits the session or the network drops, the tab stays open.
  • Press Enter in the terminal window to reconnect automatically; press Enter again to retry if reconnection fails.
  • Connection timeout is capped at 30 seconds; the status bar shows remaining seconds live, and on failure displays the first error line with troubleshooting hints.

11. Common Troubleshooting

SymptomTroubleshooting
SmartScreen says "Windows protected your PC"Normal prompt for unsigned software — click "More info" → "Run anyway"; verify the sha256 first
Garbled text in the terminalIn the Settings Center switch the encoding to GBK or GB18030 (matching the server encoding); applies to new connections
Cannot parse privateKey: Unsupported key formatUpgrade to v2.3.2+; PKCS#8 keys generated by older versions are converted automatically — no need to regenerate
Authentication failedRe-enter the password when prompted; if "Save session" was checked, the saved password overrides your input on the next connection
Connection timeoutCheck host address, port, firewall and the server's sshd status; timeout cap 30 seconds
"File in use" errorA single-instance lock exists since v1.4.1; on older versions, check Task Manager for leftover EasySSH processes
Forgot password / want to change a saved passwordEdit or delete the session record, then reconnect and check save

For more questions, see the FAQ page; debug logs are at %TEMP%\easyssh-debug.log.

Developer Guide

This section is for contributors who want to participate in EasySSH development. The full content lives in the repository docs source docs-src/develop.md and CONTRIBUTING.md.

Tech Stack

v5 is built entirely on open-source components: Rust 2021 (core language), Tauri 2 (desktop app framework, Windows x64), russh 0.45 (SSH/SFTP protocol implementation), xterm.js 5.x + Fit/Search plugins (terminal rendering and auto-fit). Build tools: Cargo (single-file portable exe, zero-extraction direct replacement).

Directory Structure

EasySSH/
  src-tauri/       # Rust core: ssh/sftp/xfer connection & transfer, configstate config, updater signed upgrades
ui/js/           # Frontend modules: terminal/sftp/settings etc., modularized
  preload.js       # Preload script: safely exposes IPC interfaces to the renderer
  renderer.js      # Renderer: UI logic, xterm terminal, tabs, settings center, SFTP panel
  index.html       # App page structure
  style.css        # App styles (5 skins, custom-drawn title bar)
  assets/          # In-app static assets (xterm library loaded from assets/ so it works after asar packaging)
  package.json     # Dependencies and build config
  release/         # electron-builder output: EasySSH-<version>.exe
  dist/            # electron-packager output: folder edition

Runtime data (travels with the exe directory): config.json (sessions & settings), keys/ (key files).

Local Development

Requirements: Node.js ≥ 18, Windows (the output is the Windows portable build).

npm install
npm start            # Run locally for debugging
  • UI errors are shown in red inside the app (global script error display since v1.5.1);
  • For SSH connection issues check the debug log %TEMP%\easyssh-debug.log;
  • Restart npm start after changing main-process code.

Packaging & Release

npm run build:exe    # electron-builder --win portable, outputs release/EasySSH-<version>.exe
npm run package:win  # Fallback: electron-packager folder edition, outputs to dist/

Before releasing a new version, be sure to: ① update version in package.json; ② add a ### v<version> (<date>) entry to the README "Version History" (the README is the authoritative source); ③ name the artifacts EasySSH-<version>.exe and EasySSH-<version>-win32-x64-portable.zip. See the contribution guide for details.

Contributing

Read CONTRIBUTING; follow the Code of Conduct; do not submit security vulnerabilities publicly — use the Security Policy channel (security@easyssh.cn).

Automatic Website Sync

The website syncs automatically from repository build artifacts: the sync script tools/sync.js (zero-dependency Node ≥18, idempotent) runs every 5 minutes — parsing the README to extract intro/features/history entries; scanning release/ and dist/ artifacts and computing sha256 via streaming; copying artifacts to the site's downloads/ and generating SHA256SUMS; regenerating site-data.json (the site's single data source). As long as developers update the README history properly and produce files following the naming conventions, the website automatically shows new versions and downloads.

12. What's New in v5.0

Terminal split view: the toolbar "Split" button or keyboard shortcut toggles single / left-right / top-bottom / quad layouts; drag dividers to adjust proportions (automatically remembered); mirrored panes show the same session read-only.

Global command palette: press Ctrl+Shift+P anywhere to open it; filter sessions and common actions by initials, then press Enter to execute.

Script library macros: create macros on the quick commands page (multiple commands executed in sequence, with variable placeholders such as ${{host}}) to complete routine checks in one click.

Transfer queue: SFTP transfers support pause/resume, priority adjustment and optional throttling; large-file transfers resume from breakpoints, even after restarting the app.

Proxy and jump hosts: session editing supports SOCKS5/HTTP proxies or ProxyJump chains (up to 3 hops, automatically reusing stored session credentials).

Light/dark themes: switch between dark and light themes in the Settings Center with one click, following the Emerald design system.

Secure upgrades: online upgrade packages are verified with Ed25519 signatures; failed upgrades automatically roll back to the previous version, with full config and session compatibility.

All of these features are available since v5.0.0 and continue to be enhanced.
