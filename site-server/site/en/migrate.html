Migration Guide

Moving from Xshell / PuTTY / Termius / OpenSSH config to EasySSH · migrate your whole session library in about 10 minutes

Contents

Overview · 1. Bulk Session Import · 2. Migrating PuTTY .ppk Keys · 3. OpenSSH config Import · 4. Jump Host (ProxyJump) Example · 5. Private Key File Permissions · 6. Migration FAQ

Overview

EasySSH ships with a one-click import for existing sessions: it reads Xshell sessions stored on your machine, PuTTY sessions from the Windows registry, Termius export JSON, and OpenSSH config files. Combined with JSON import/export (automatically sanitized) and the Ed25519 key generate / install / diagnose tools, almost every migration scenario can be completed without re-typing sessions by hand.

Source toolHow EasySSH imports itCredentials migrated?
XshellReads the local session manager's .xsh files automatically (compatible with multiple NetSarang directory layouts)Host / port / username; passwords are not migrated
PuTTYReads PuTTY sessions from the registry automatically (SSH only)Host / port / username; passwords are not migrated
TermiusImports a Termius JSON export (usernames resolved by credential id)Host / port / username; passwords are not migrated
OpenSSHImports a ~/.ssh/config fileHost / port / username / jump chain; passwords are not migrated

Imports are deduplicated by host + port + username and follow the same sanitization rules as the JSON import (no passwords included), then land in a per-source group. Just type the password once on first connect.

1. Bulk Session Import

The import entry lives in the "External" button group on the sidebar / Settings (next to "New group / Export / Import"). All four sources share the same flow:

  1. Open the import entry: launch EasySSH and find the "External" button group at the bottom of the session sidebar, then open the external-session import panel.
  2. Pick a source: choose the tool you are migrating from — Xshell / PuTTY / Termius / OpenSSH config.
  3. Provide the data source (varies by source):
    • Xshell: EasySSH scans the local NetSarang session directories automatically (multiple version layouts supported) and lists available .xsh sessions; if your install path is unusual you can point it to the session folder manually.
    • PuTTY: sessions are read directly from the registry (SSH sessions only, via a hidden-window reg query — no extra dependencies).
    • Termius: first export a JSON file from Termius using its own export feature, then select that file in the import panel; usernames are resolved automatically from credential ids.
    • OpenSSH config: select your ~/.ssh/config file (a custom path works too); wildcard Host blocks are skipped automatically.
  4. Review and import: confirm the session list and run the import; duplicates (same host + port + username) are skipped and reported.
  5. Enter credentials once: imported sessions contain no passwords. Type the password on first connect, or switch to key-based authentication (see sections 2 and 5).
Tip: imported sessions are grouped by source (e.g. "Xshell", "PuTTY"), so you can verify them one by one after migration and re-file them into your own groups.

2. Migrating PuTTY .ppk Keys

PuTTY uses its own .ppk private key format; EasySSH uses standard OpenSSH-format keys. Two ways to migrate:

Option A: Convert with PuTTYgen (works with any version)

  1. Open PuTTYgen bundled with PuTTY (Start menu → PuTTY → PuTTYgen).
  2. Click Load and pick your existing .ppk private key (you will be asked for its passphrase first if it has one).
  3. From the menu choose Conversions → Export OpenSSH key (pick "Export OpenSSH key" — the new-format export, not the SSH-1 one).
  4. Choose a save location (e.g. keys\myserver.openssh) and save.
  5. In EasySSH's session editor, set the authentication method to "Private key file" and select the exported OpenSSH key.

Option B: Direct .ppk import (since v5.2.0)

Starting with v5.2.0, EasySSH supports importing .ppk files directly: just select the .ppk file as the private key in the session editor.

  • Unencrypted keys (no passphrase): converted to OpenSSH format automatically — no manual steps.
  • Passphrase-protected ppk files: remove the passphrase in PuTTYgen first (load the key, leave Key passphrase empty, Save private key), or export to OpenSSH format via Option A before importing.
Tip: before deleting the original .ppk, confirm the new key logs into the target server fine. EasySSH's key tools can also install the public key onto the currently connected server in one click with proper 700/600 permissions.

3. OpenSSH config (~/.ssh/config) Import

If you maintain a ~/.ssh/config on Linux/macOS or Windows, import it directly into EasySSH:

  • Supported directives: Host, HostName, Port, User, and ProxyJump (converted into EasySSH jump chains — see the next section).
  • Automatically skipped: wildcard Host blocks (e.g. Host *.corp) produce no sessions; other directives such as IdentityFile and ProxyCommand are not converted for now.
  • Deduplication: sessions matching an existing host + port + username are skipped.
  • How to: sidebar / Settings "External" button group → choose "OpenSSH config" → point to the config file → import.
Note: a ProxyJump directive references a target session by name. Make sure a session with that name exists in EasySSH — importing all of your sessions first usually wires the jump chains up automatically.

4. Jump Host (ProxyJump) Example

EasySSH lets you set an existing saved session as the jump host for another session — up to 3 hops — with each hop reusing that saved session's own credentials: however the jump host normally logs in (password or key) is exactly how EasySSH logs into it. Nothing to re-enter.

Example scenario

Goal: reach the internal server app01 through the jump host bastion. The equivalent OpenSSH configuration would be:

Host app01
    HostName 10.0.1.20
    User deploy
    Port 22
    ProxyJump bastion

Configuring it in EasySSH

  1. Make sure the jump session exists: first save a session named "bastion" in EasySSH (the bastion's public address and its account — password or key), and confirm it connects on its own.
  2. Edit the target session: open or create the "app01" session (10.0.1.20 / 22 / deploy).
  3. Build the jump chain: in the session editor's "Proxy & jump hosts" section, choose ProxyJump and pick the saved "bastion" session as the first hop. EasySSH connects to the jump host first, then forwards to the target through it.
  4. Save and connect: on connect, EasySSH reuses the saved "bastion" session's credentials to log into the jump host and then reaches app01 directly. Proxy and jump settings persist with the session and are restored automatically on reconnect.

For two- or three-hop routes (local → bastion → inner-jump → db01), simply append more saved sessions to the jump chain in order — up to 3 hops.

5. Private Key File Permissions

  • Windows: never make private key files (those under keys/ and any migrated OpenSSH keys) readable by everyone. Right-click the file → Properties → Security: remove read access for "Everyone / Users" and keep only your own account. Avoid shared folders and cloud-sync folders for keys.
  • Carrying keys around: EasySSH is portable — keys travel with the keys/ folder next to the exe. When moving them via USB drives, watch out for inherited permissions on the destination machine and tighten the ACL again after copying.
  • Unencrypted keys: a passphrase-free key converted from PuTTYgen has no protection at all — anyone holding the file can log into your servers. For important servers, consider generating a fresh Ed25519 key pair in EasySSH, deploying it with the one-click "install to current connected server" tool, and retiring the old key.
  • config.json plaintext note: passwords are stored in plain text in config.json when "Save session" is checked — use it only in trusted environments.

6. Migration FAQ

Q1: Why don't imported sessions have passwords?

Imports follow the sanitization rules and never migrate passwords (the same rules as JSON import/export). Type the password once on first connect; for password-free login, switch to key authentication (see sections 2 and 5).

Q2: The PuTTY import list is empty?

PuTTY sessions live in the registry and EasySSH only imports SSH sessions (Telnet/Serial sessions are skipped). Make sure the sessions were actually saved in PuTTY on this machine (not just opened ad-hoc), and run EasySSH as the same Windows user that installed PuTTY.

Q3: Some sessions are missing after an OpenSSH config import?

Wildcard Host blocks (e.g. Host *.corp) are skipped automatically, and only Host/HostName/Port/User/ProxyJump are converted. Create sessions for wildcard-matched hosts manually.

Q4: Importing a passphrase-protected .ppk fails?

EasySSH auto-converts unencrypted .ppk files (since v5.2.0). For passphrase-protected ones, remove the passphrase in PuTTYgen first, or export to OpenSSH format via Conversions → Export OpenSSH key before selecting it.

Q5: The jump chain fails to connect — what should I check?

First connect to the jump session on its own to verify its credentials; then check that the jump chain on the target session points to the right session names. Chains allow up to 3 hops, and each hop reuses that saved session's own credentials — if a jump host's password changed, update the jump session itself.
