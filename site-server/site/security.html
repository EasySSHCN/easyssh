# 如何报告安全漏洞

请勿通过公开 Issue 报告安全漏洞，以免在修复发布前被恶意利用。
报告渠道：软件内「💬 使用反馈」
打开 EasySSH，点击工具栏的 「💬 反馈」按钮： 类型选择「问题反馈」，内容中注明「安全漏洞报告」并描述漏洞类型、影响与复现步骤； 务必填写联系方式（邮箱 / GitHub / 微信等），以便我们就修复与致谢事宜与你联系。

反馈内容经 AES-256-GCM 加密信封传输（与在线升级同族加密协议，带时效签名防重放）， 仅管理员可在官网后台查看，不会公开显示；只有已修复且适合公开的内容，才会出现在下载页「使用反馈精选 TOP10」。

报告请尽量包含：

  1. 漏洞类型与影响描述（可被利用的场景）
  2. 复现步骤或概念验证（PoC，可注明「仅管理员可见」）
  3. 受影响的 EasySSH 版本号（软件「设置 → 关于」可查看）
  4. 你希望的署名方式（或希望匿名，可在反馈中注明）

# 响应时限承诺

阶段承诺时限
确认收到报告3 个工作日内
初步评估与定性7 个工作日内

若漏洞涉及第三方依赖（如 russh、tokio、Tauri 2、xterm.js），我们会在评估后同步向上游反馈或升级依赖版本。

# 升级链路签名（Ed25519）

自 v5.0 起，在线升级清单使用 Ed25519 非对称签名：发布机私钥签名、客户端内置公钥验签， 验签失败的清单将被拒绝安装——即使升级加密主密钥泄露，攻击者也无法伪造升级包。

签名公钥指纹（SHA-256 前 16 hex）：48fa5a439c7dc385
公钥（base64）：XjWJX7593VwDhOElMMHAOnDWFWy71cgBkNXv/vERGHg=
私钥仅由项目发布机持有，不随任何安装包/源码分发。若本指纹与你在软件内看到的不一致，请立即停止升级并通过反馈渠道联系我们。

# 安全相关说明（用户须知）

  • 密码保存机制：会话密码保存在 exe 同目录的 config.json 中，为明文保存。不可信环境请勿勾选「保存会话」。
  • 代码签名：产物 exe 目前未做代码签名，首次运行 SmartScreen 会提示一次，点「仍要运行」即可；请始终从官网 easyssh.cn 下载，并用下载页提供的 sha256 校验产物完整性。
  • 数据便携性：会话、设置、密钥（keys/ 目录）均存放在 exe 同目录并随文件夹携带，请妥善保管该目录，避免泄露私钥与密码。
  • 调试日志：%TEMP%\easyssh-debug.log 可能包含连接诊断信息，提交问题前请自行检查是否含敏感内容。
