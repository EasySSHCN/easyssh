# EasySSH — Windows 绿色版 SSH 终端

> ## 🌐 官方网站：**https://EasySSH.CN**

自研轻量 SSH/SFTP 终端（参考 SecureCRT 使用体验，代码 100% 原创）。
技术栈：Electron + xterm.js + ssh2 + iconv-lite（纯开源组件）。

> **【项目维护规则 — 长期有效】**
> 每次版本更新必须同步更新本文件的「版本更新历史记录」，包括：版本号、日期、新增/修复内容。
> 产物文件名必须带版本号（EasySSH-<version>.exe / EasySSH-<version>-win32-x64-portable.zip）。

## 使用（绿色版，免安装）

1. 下载 `release/EasySSH-<版本号>.exe`（单文件，双击即用）或 `dist/EasySSH-<版本号>-win32-x64-portable.zip`（解压用）。
2. 首次运行 SmartScreen 提示未签名 → 点"仍要运行"。
3. 会话与设置统一存 exe 同目录 `config.json`（旧版 `sessions.json`/`settings.json` 自动迁移），均随文件夹携带。

## 功能总览

- 多标签 SSH（密码/私钥、keyboard-interactive 自动适配）
- **密钥登录**（v2.3.0 起）：一键生成 Ed25519 密钥对、用密码连接一键安装公钥到服务器（含权限/SELinux 修正与回读校验）、密钥失败自动诊断真实原因
- **本地端口转发**（v2.7.0 起）：`127.0.0.1:本地端口 → 目标主机:目标端口`，配置随会话持久化，断线重连自动恢复转发，安全访问内网服务
- 断开后按回车自动重连
- **SFTP 文件传输**（浏览/上传/双击下载，支持按服务器编码做文本转换传输）
- **快捷命令栏**（自定义命令按钮，一键发送，支持添加/编辑/删除）
- **应用图标**（v2.8.0 起）：多尺寸深色圆角蓝青渐变闪电图标，融入 exe 与任务栏
- **设置**：字体、字号、编码（UTF-8/GBK/GB18030/Big5）、5 款皮肤配色全局生效（含自绘标题栏跟随主题）
- **在线升级**（v2.5.0 起，AES 加密通道 + 原地换名替换，见下方「在线升级」章节）
- 窗口自适应、5000 行回滚、keepalive、单实例

## 在线升级（v2.5.0 起提供）

- **自动检测**：打开软件后自动探测一次新版本；运行期间每 1 小时自动探测一次。发现新版本时界面顶部出现提醒条，也可在「设置 → 检查更新」手工检测。
- **加密通道**：检测接口（官网 `/api/update/check`）返回 AES-256-GCM 加密信封（带 HMAC 时效签名，防篡改/防重放）；安装包以 `EasySSH-<ver>.exe.enc` 加密流形式下载（AES-256-CTR + HMAC-SHA256），下载完成后客户端流式解密并做 HMAC 与 SHA-256 双重校验，任何校验失败都不会落地安装。协议实现见 `updater.js`（客户端）与官网 `tools/update-crypto.js`（服务端）。
- **版本范围**：在线升级渠道仅服务 **v2.5.0 及以上**版本（`MIN_UPGRADE_VERSION = 2.5.0`），更早版本请手动下载安装包升级。
- **替换方式（原地换名，无脚本）**：下载校验通过后点「完成升级」，程序利用 Windows"允许改名运行中的 exe"的特性，由旧进程在退出前自己完成三步替换——旧 exe 改名 `.bak` → 新 exe 顶替原文件名（桌面快捷方式无缝沿用）→ 分离启动新版（`--upgraded`）。全程不生成 bat/PowerShell 脚本，杀软无可标记对象；任一步被拦截会自动恢复旧版并给出降级手动路径。启动时自动清理 `.bak` 备份与下载残留。
- **⚠ 脱敏说明（SANITIZED）**：升级主密钥保存在本目录 `update-keys.json`（打包时随 exe 携带，**绝不随源码 zip / 版本库对外发布**）；对外发布的脱敏占位样例为 `update-keys.example.json`（内容 `<REDACTED>` 并标注 SANITIZED）。官网同步工具打包源码 zip 时会自动剔除该文件。

- 安装命令改为逐段容错:任何一段(如目录不可写)失败都会被回读校验拦截并原样展示服务器报错,不再出现"假成功"

### v2.3.4 (2026-10-28)
- 修复:**「安装到当前已连服务器」成功后改用密钥登录仍报 "All configured authentication methods failed"** —— 旧安装命令只设置了 ~/.ssh 与 authorized_keys 权限,当服务器家目录(如 /root)为组/其他可写时,sshd StrictModes 会静默拒绝读取 authorized_keys;SELinux 系统(CentOS/RHEL)还可能因上下文不对拒绝。现在安装公钥时自动执行 `chmod g-w,o-w ~` 与 `restorecon -R ~/.ssh`(存在 restorecon 时),安装后回读校验公钥确实写入,并通过 `sshd -T` 检测服务器公钥认证开关
- 若服务器 sshd 配置了 `PubkeyAuthentication no`,安装后会明确提示需在 /etc/ssh/sshd_config 开启公钥认证并重启 sshd,不再"安装成功"却登不上
- 密钥认证失败的中文提示同步更新,引导重新执行一次「安装到当前已连服务器」完成权限修正

### v2.3.3 (2026-10-28)
- 修复:**密钥连接无法作为会话保存** —— "保存会话"只在密码认证时生效,密钥认证的连接重启后丢失,点左侧连接记录只能回到密码方式,需重新生成/填写密钥。现在密钥连接同样保存(记录认证方式、私钥路径、口令),重启后点击连接记录自动恢复为"私钥文件"方式并回填私钥路径,直接连接即可

### v2.3.2 (2026-10-28)
- 修复:**一键生成密钥后连接报 "Cannot parse privateKey: Unsupported key format"** —— ssh2 的密钥解析器不支持 PKCS#8("BEGIN PRIVATE KEY")格式,而 v2.3.0 起一键生成的私钥恰是 PKCS#8,导致永远无法用生成的密钥登录

- 连接时自动兼容旧密钥文件:检测到旧版本生成的 PKCS#8 私钥(Ed25519/RSA/EC)自动转换为 ssh2 可解析格式,旧密钥无需重新生成即可继续使用
