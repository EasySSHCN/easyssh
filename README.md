# EasySSH v5 — Rust + Tauri 2 的 Windows 绿色版 SSH/SFTP 终端

> ## 🌐 官方网站：**https://EasySSH.CN**
> 安装包下载、在线升级、使用文档的唯一官方渠道，请认准 **https://EasySSH.CN**

[![GitHub release](https://img.shields.io/badge/version-5.0.0--alpha.1--dev-blue)](https://github.com/EasySSHCN) [![官网](https://img.shields.io/badge/官网-easyssh.cn-10B981)](https://easyssh.cn) [![License](https://img.shields.io/badge/license-MIT-green)](LICENSE)

EasySSH v5 是 [EasySSH v4](https://github.com/EasySSHCN/easyssh)（Rust + Tauri 2 + russh 内核重写版）的下一代主线仓库，围绕**安全、健壮性、执行效率、功能增强、简化流程、美化 UI** 六大方向升级。

- **效率：SFTP 传输进度事件节流**——由每 256KB 一次改为 100ms 或 ≥1% 增量推送，大文件传输不再形成事件风暴

- 新增**密钥登录失败自动诊断**:密钥认证失败时,若该服务器仍有在线的密码连接,自动到服务器上采集真实原因——sshd 公钥认证开关/AuthorizedKeysFile/PermitRootLogin/多步认证配置、家目录与密钥文件权限属主、SELinux 状态、公钥是否真的写入、sshd 日志中的拒绝记录——并直接在连接面板给出逐条结论,不再盲目重试
- 安装命令改为逐段容错:任何一段(如目录不可写)失败都会被回读校验拦截并原样展示服务器报错,不再出现"假成功"
### v2.3.4 (2026-10-28)
- 修复:**「安装到当前已连服务器」成功后改用密钥登录仍报 "All configured authentication methods failed"** —— 旧安装命令只设置了 ~/.ssh 与 authorized_keys 权限,当服务器家目录(如 /root)为组/其他可写时,sshd StrictModes 会静默拒绝读取 authorized_keys;SELinux 系统(CentOS/RHEL)还可能因上下文不对拒绝。现在安装公钥时自动执行 `chmod g-w,o-w ~` 与 `restorecon -R ~/.ssh`(存在 restorecon 时),安装后回读校验公钥确实写入,并通过 `sshd -T` 检测服务器公钥认证开关
- 若服务器 sshd 配置了 `PubkeyAuthentication no`,安装后会明确提示需在 /etc/ssh/sshd_config 开启公钥认证并重启 sshd,不再"安装成功"却登不上
- 密钥认证失败的中文提示同步更新,引导重新执行一次「安装到当前已连服务器」完成权限修正
### v2.3.3 (2026-10-28)
- 修复:**密钥连接无法作为会话保存** —— "保存会话"只在密码认证时生效,密钥认证的连接重启后丢失,点左侧连接记录只能回到密码方式,需重新生成/填写密钥。现在密钥连接同样保存(记录认证方式、私钥路径、口令),重启后点击连接记录自动恢复为"私钥文件"方式并回填私钥路径,直接连接即可
- 修复:**「一键生成本机密钥对」每次都覆盖 keys/ 下已有密钥对**,导致服务器 authorized_keys 里的旧公钥与新私钥不再匹配。现在检测到已有密钥对时直接复用,不再重新生成
### v2.3.2 (2026-10-28)
- 修复:**一键生成密钥后连接报 "Cannot parse privateKey: Unsupported key format"** —— ssh2 的密钥解析器不支持 PKCS#8("BEGIN PRIVATE KEY")格式,而 v2.3.0 起一键生成的私钥恰是 PKCS#8,导致永远无法用生成的密钥登录
- 私钥改用标准 OpenSSH 格式("openssh-key-v1",未加密)生成,ssh2 直接可用(已通过完整 SSH 握手签名验证 + ssh-keygen 校验)
- 连接时自动兼容旧密钥文件:检测到旧版本生成的 PKCS#8 私钥(Ed25519/RSA/EC)自动转换为 ssh2 可解析格式,旧密钥无需重新生成即可继续使用

## 构建（Windows 10/11 x64）

前置：Rust stable (MSVC)、VS Build Tools、Node.js。

```powershell
# 安装依赖（前端为原生 HTML/JS，无 npm 依赖时跳过）
cargo build
# 完整发布构建（NSIS 安装器/便携版/绿色 zip/源码包）
powershell -ExecutionPolicy Bypass -File scripts\build-v4-local.ps1
```

`tools/`（NSIS、MinGit）与 `update-keys.json` 为本机构建私有数据，不入库。
