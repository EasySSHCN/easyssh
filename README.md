自研轻量 SSH/SFTP 终端（参考 SecureCRT 使用体验，代码 100% 原创）。
技术栈：Electron + xterm.js + ssh2 + iconv-lite（纯开源组件）。

> **【项目维护规则 — 长期有效】**
> 每次版本更新必须同步更新本文件的「版本更新历史记录」，包括：版本号、日期、新增/修复内容。
> 产物文件名必须带版本号（EasySSH-<version>.exe / EasySSH-<version>-win32-x64-portable.zip）。

## 使用（绿色版，免安装）

1. 下载 `EasySSH-<版本号>-win32-x64-portable.zip`（绿色便携包，v3.0.7 起取消单文件 exe），解压到任意目录（建议非系统临时目录）后运行 `EasySSH.exe`。
2. 首次运行 SmartScreen 提示未签名 → 点"仍要运行"。
3. 会话与设置统一存 exe 同目录 `config.json`（旧版 `sessions.json`/`settings.json` 自动迁移），均随文件夹携带。

## 功能总览

- **多标签 SSH 会话**：一个窗口管理多台服务器，支持密码 / 私钥登录，keyboard-interactive 自动适配
- **密钥登录**（v2.3.0 起）：一键生成 Ed25519 密钥对、用密码连接一键安装公钥到服务器（含权限/SELinux 修正与回读校验）、密钥失败自动诊断真实原因
- **端口转发**（v2.7.0 起）：本地端口转发（`127.0.0.1:本地端口 → 目标主机:目标端口`）+ **SOCKS 4/5 动态转发**（v2.8.1 起，本地端口秒变经 SSH 加密隧道的 SOCKS 代理）；配置随会话持久化，断线重连自动恢复
- **SFTP 文件传输**：远程目录浏览 / 上传 / 双击下载，支持按服务器编码做文本转换传输
- **快捷命令栏**：自定义常用命令按钮，一键发送，支持添加 / 编辑 / 删除
- **主密码保护**（v3.0.0 起）：可选启用；密钥经 PBKDF2 + AES-256-GCM 加密落盘，启动全屏解锁，防拷贝破解
- **断线自动恢复**：断开后按回车自动重连；端口转发、keepalive 防空闲断开
- **多编码支持**：UTF-8 / GBK / GB18030 / Big5 自动与手动识别，乱码服务器不再愁
- **5 款皮肤主题**：深浅配色全局切换，自绘标题栏跟随主题
- **绿色便携**：zip 解压即用（v3.0.7 起唯一发行形态），不写注册表、免管理员权限、整个文件夹可拷走即用；桌面快捷方式自动补建
- **安全在线升级**（v2.5.0 起）：AES-256-GCM 信封 + 安装包加密流双重校验，检测 / 下载 / 替换全程加密，原地换名无缝升级、可回滚
- **现代终端体验**：xterm.js 内核，窗口自适应、5000 行回滚、终端内搜索、窗口尺寸记忆

## 在线升级（v2.5.0 起提供）

- **自动检测**：打开软件后自动探测一次新版本；运行期间每 1 小时自动探测一次。发现新版本时界面顶部出现提醒条，也可在「设置 → 检查更新」手工检测。
- **加密通道**：检测接口（官网 `/api/update/check`）返回 AES-256-GCM 加密信封（带 HMAC 时效签名，防篡改/防重放）；安装包以 `EasySSH-<ver>.exe.enc` 加密流形式下载（AES-256-CTR + HMAC-SHA256），下载完成后客户端流式解密并做 HMAC 与 SHA-256 双重校验，任何校验失败都不会落地安装。协议实现见 `updater.js`（客户端）与官网 `tools/update-crypto.js`（服务端）。
- **版本范围**：在线升级渠道仅服务 **v2.5.0 及以上**版本（`MIN_UPGRADE_VERSION = 2.5.0`），更早版本请手动下载安装包升级。
- **替换方式（原地换名，无脚本）**：下载校验通过后点「完成升级」，程序利用 Windows"允许改名运行中的 exe"的特性，由旧进程在退出前自己完成三步替换——旧 exe 改名 `.bak` → 新 exe 顶替原文件名（桌面快捷方式无缝沿用）→ 分离启动新版（`--upgraded`）。全程不生成 bat/PowerShell 脚本，杀软无可标记对象；任一步被拦截会自动恢复旧版并给出降级手动路径。启动时自动清理 `.bak` 备份与下载残留。
- **⚠ 脱敏说明（SANITIZED）**：升级主密钥保存在本目录 `update-keys.json`（打包时随 exe 携带，**绝不随源码 zip / 版本库对外发布**）；对外发布的脱敏占位样例为 `update-keys.example.json`（内容 `<REDACTED>` 并标注 SANITIZED）。官网同步工具打包源码 zip 时会自动剔除该文件。

### v3.0.4 (2026-10-30)

### v3.0.2 (2026-10-30)
- 修复**从临时目录副本发起升级仍会"原地替换"临时副本**：v3.0.0→v3.0.1 在线升级时，「完成升级」替换并启动的是 %TEMP%（如 C:\Users\…\AppData\Local\Temp）里的解压副本，用户安装目录（如 P:\Program Files (x86)\EasySSH）里的旧版原样未动；此后临时副本再发起升级，安装包依旧下载到临时目录。现在升级模块启动即检测当前 exe 是否驻留系统临时目录（`isTempResident()`）：驻留时升级横幅明确警告"本次升级无法替换真实安装目录"，且**拒绝执行原地替换**并给出手动修复指引（关闭软件 → 把新 exe 移回安装目录覆盖旧版，或从 easyssh.cn 重新下载放入），不再制造"升级成功"的假象

### v3.0.1 (2026-10-30)
- 修复**在线升级在便携版下下载与替换位置全错**：此前下载目录取 `app.getPath('exe')`，而便携版运行时进程位于 %TEMP% 解压目录，安装包被下到 `Temp\...\updates`；替换环节误用的 `PORTABLE_EXECUTABLE_PATH` 环境变量并不存在（实际注入的是 `PORTABLE_EXECUTABLE_FILE`），导致「完成升级」改名的、顶替的、重启打开的全是临时副本，用户桌面上双击的旧版原样未动。现在统一用 `realExePath()`（PORTABLE_EXECUTABLE_FILE → 回退）定位真实 exe：安装包下载保存到**运行软件所在目录的 updates\\ 子目录**，「完成升级」在原目录完成 旧版改名 .bak → 新版顶替原名 → 分离启动新版的替换，桌面快捷方式无缝沿用，旧版自动备份可回滚
